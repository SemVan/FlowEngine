# Краны: один общий endstop

Актуальный `config/device_map.yaml` и личный профиль задают wash_valve → A,
sheath_valve → B, sample_valve → C. Каждый кран имеет один микрик; все микрики
запараллелены на входе Z. Точное имя входа в M119 выбирается оператором на
странице `/valves`. Значение `null` блокирует движение: имя канала не угадывается.

## Архитектура и состояния

`hardware/valves.py: ValveSubsystem` принадлежит текущему GcodeSender. Он хранит
общий lock, единственный `shared_valve_endstop`, active_valve и runtime state
каждого крана: UNCONFIGURED, CALIBRATED_UNREFERENCED, HOMING, REFERENCED, MOVING,
FAULT. `referenced` существует только в текущем соединении и не пишется в YAML.

`ValveConfig` хранит имя/ось, направление к HOME (противоположное вычисляется),
скорости seek/latch, backoff/pull_off, watchdog, A/B и calibrated.
В старых профилях направление наследуется из существующего home_direction оси,
старые A/B остаются видимыми, но calibrated по умолчанию false.
`home_position` сохранён для чтения старых профилей; HOME больше не означает A/B.
Положения A/B — подписанные координаты относительно HOME; положительный Count
означает положительное направление Marlin, а не обязательно движение от HOME.
Реальное безопасное направление подтверждает оператор.

Все клапанные движения проходят через этот lock. Home All держит его на весь
последовательный цикл; перед следующим мотором обязательно проверяется OPEN.
Обычный sender.home на клапанной оси также использует ValveSubsystem.
EndstopHoming и raw G28 запрещены для кранов. Совместные G1 с клапанными осями
отклоняются. Старые move_to на сохранённое A/B адаптируются в set_valve;
произвольный jog допускается только в commissioning. Двухграничный
calibrate_valve/seek для кранов запрещён.

## Home и остановка

OPEN → fast seek → TRIGGERED → M410/M400 → release до OPEN → дополнительный
backoff → slow latch → TRIGGERED → M410/M400 → HOME=0 → release до OPEN →
дополнительный pull_off → проверка OPEN → REFERENCED.

Поиск переиспользует `hardware/endstop_seek.py: seek_switch`, как X/Y.
В клапанном слое учитывается Count точного latch: общий primitive после M410
перебазирует G92 в абсолютный Count, поэтому после release восстанавливается
клапанная координата `(Count - Count_HOME) / steps_per_unit`.
Это не меняет primitive или калибровку X/Y. Если Count недоступен, используется
координатная опора G92/M114 R; отсутствие и координат, и Count приводит к ошибке.

Обычные A/B и commissioning-движения контролируются M119 в ходе движения;
M114 R подтверждает фактическое достижение координаты с допуском половины шага.
M400 не блокирует опрос в ходе такого движения. После неожиданного TRIGGERED
отправляется M410, текущий кран получает FAULT/REFERENCE_LOST, процедура
прерывается, очередь блокируется до reconnect. Stop/ошибка связи сбрасывают
достоверность координат. Калибровка A/B остаётся в профиле.

Для клапанной операции M211 временно выключается, исходное ON/OFF читается
перед операцией и восстанавливается после неё. При ошибке сначала выполняется
остановка; восстановление возможно лишь при работающей связи. После обрыва
связи следует отдельно проверить состояние M211 перед продолжением.

Остановка здесь host-supervised: M119 опрашивается с интервалом 40 мс плюс время
ответов транспорта/прошивки; после обнаружения TRIGGERED следующая команда —
M410. Это не обещание нулевой аппаратной задержки. На первом моторе необходимо
подтвердить, что Marlin отвечает на M119 во время G1 и выполняет M410 вовремя.

При старте с TRIGGERED источник UNKNOWN. Home/Home All не запускаются. В сервисе
оператор выбирает один мотор и задаёт короткий шаг ± (не более 0.5 единицы оси).
Программа не ищет источник другими моторами; при появлении OPEN останавливает
выбранный мотор. Такой сервис сбрасывает reference всех кранов.

## Первичная калибровка

1. Откройте Valves и проверьте общий Z-вход кнопкой «Прочитать M119».
2. Сохраните канал, направление и скорости. Изменение настройки требует новой
   калибровки A/B; старые числа сохраняются для справки.
3. У одного выбранного крана нажмите Calibrate: выполняется полный Home с pull-off.
4. Короткими шагами от HOME установите реальное механическое A, нажмите Сохранить A.
5. Продолжите от HOME до B, нажмите Сохранить B. Можно сохранять B раньше A,
   если B механически ближе к HOME. Для возврата ближе начните Calibrate заново.
6. Только после сохранения обеих различных позиций calibrated становится true.
   Сохраняются координаты и доступен отчёт steps_from_home, полученный из Count.
7. Home устанавливает reference; A/B остаются UNKNOWN, пока явно не достигнута
   сохранённая позиция. Go A/B требуют calibrated и referenced.

Настройки и A/B записываются атомарно в активный личный профиль; для default —
в пользовательский overlay device_map.yaml. Reconnect/restart/profile apply не
двигают моторы и сбрасывают reference. REFERENCED не восстанавливается из YAML.
Go A/B подчиняется существующему runtime.motion.enabled; commissioning/Home и
сервис доступны для первоначальной настройки при отключённом обычном движении.

## API процедур

```python
await sender.home_valve("sample")
await sender.set_valve("sample", "A")
await sender.set_valve("sample", "B")
await sender.valves.home_all()
```

```yaml
steps:
  - op: home_valve
    name: sample_valve
  - op: set_valve
    name: sample_valve
    position: B
```

Операции завершаются только после окончания движения и проверки сигнала.
Runner ждёт каждую операцию, поэтому следующий кран/насос не запускается раньше.
Существующий set_valve совместим с новым механизмом; автоматического слепого
Go или скрытого Home перед Go нет. G1/G28 в процедурах кранов не нужны.

## Проверка ОДНОГО мотора на железе

После сообщения о перегреве аппаратная проверка приостановлена. Исправление
ниже проверено только программно. Физическое соответствие кранов осям,
направление C и рабочий/удерживающий ток требуют отдельной проверки до движения.
Приведённый далее порядок не является разрешением запускать моторы сейчас.

1. Запустите актуальный FlowEngine с вашим личным профилем. Начните только с
   sample_valve / C либо одного другого физически проверенного мотора. Home All
   пока не нажимайте. Обеспечьте доступ к физическому выключению привода.
2. При неподвижных моторах прочитайте M119. Вручную нажмите/отпустите микрик
   только выбранного крана и повторите чтение: выбранный Z-канал должен дать
   OPEN → TRIGGERED → OPEN. Остальные краны должны освобождать свои микрики.
3. Сохраните точное имя канала. Если общий вход уже TRIGGERED, источник UNKNOWN:
   в сервисе выберите только этот мотор и освобождайте малыми шагами. Не
   перебирайте моторы автоматически. Убедитесь, что шаг действительно отводит
   механизм от микрика, и установите правильное direction_toward_home.
4. Установите небольшие скорости seek/latch, достаточный небольшой backoff и
   pull_off, watchdog для данного механизма. Нажмите Home ТОЛЬКО у этого крана.
5. Первый критерий успеха: при касании движение к микрику сразу прекращается,
   мотор не продолжает давить; выполняется отход, медленный повторный контакт
   и окончательный pull-off. В конце Shared endstop OPEN и Reference REFERENCED.
   Если это не произошло, остановите привод; к Home All не переходите.
6. Несколько раз повторите Home этого одного крана. Затем Calibrate, вручную
   сохраните A/B и проверьте Go A/Go B на малой штатной скорости. Для обычного
   движения нужен включённый существующий motion interlock после проверки.
7. Reconnect: A/B должны сохраниться, position стать UNKNOWN, reference —
   Home required, Go A/B — заблокироваться. Повторите Home выбранного крана.
8. Каждый оставшийся мотор сначала проверяется отдельно тем же способом.
   Только после этого выполняйте Home All Valves и наблюдайте строго
   последовательное движение с OPEN между моторами.

Автоматические проверки используют mock и движущийся симулятор Marlin.
В ходе прежней ручной проверки были реальные сервисные движения, после чего
оператор сообщил о перегреве и отключил аппарат. Исправление снятия удержания
проверено только на симуляторе, без запуска сервера управления и подключения COM.

## Снятие удержания после сервисного шага

Только `service_jog` после завершения движения отправляет `M18 <ось>` для
выбранного мотора; общая команда M18 без оси не используется. Успешный job
требует получения ACK на M18. Reference всех кранов остаётся сброшенным.
Обычные Home, Calibrate, commissioning jog и Go A/B этой политикой не изменены:
они сохраняют удержание и reference и требуют отдельно согласованного режима тока.

При ошибке, отмене задачи или STOP во время сервиса очередь блокируется,
отправляются M410 и отдельный запрос M18 выбранной оси. ACK аварийного запроса
не читается: старые ответы нельзя безопасно сопоставить с новой командой.
Повторный обработчик ошибки не дублирует аварийный запрос M18; автоматического
переподключения или повторения движения нет. X/Y STOP сохраняет прежнюю логику.
При аварии восстановление M211 не гарантируется; его проверяют после reconnect.

API `service_release` и UI показывают результат последнего сервисного шага:
`ACKNOWLEDGED` — получен ACK команды M18; `REQUESTED_UNCONFIRMED` — транспорт
принял аварийный запрос без подтверждения исполнения; `UNKNOWN` — отправку
подтвердить не удалось. Ни ACK, ни работа симулятора не измеряют фактический
ток обмоток. При потере USB мотор может остаться под током.

Синтаксис M18 соответствует документации Marlin:
https://marlinfw.org/docs/gcode/M018.html. Поддержку букв осей и раздельных
enable-линий конкретной прошивкой/платой необходимо проверить аппаратно.
Сервис для E0/E3 и других имён длиннее одной буквы отклоняется до команд.
Настройки M906, M500/EEPROM и таймер M18 S не меняются.

### Пробный Home со снятием удержания

`POST /api/valves/sample` с `{"action":"test_home"}` выполняет тот же
seek/release/latch/pull-off для одного выбранного крана, затем отправляет M18
только его оси. Reference после такой пробы сбрасывается; Go A/B остаются
заблокированы. Калибровка A/B и постоянные настройки не изменяются.
При ошибке/STOP/отмене используется тот же аварийный запрос отключения, что
для service_jog; при потере связи отключение остаётся неподтверждённым.
Проба не определяет направление и соответствие осей автоматически: перед
первым поиском их подтверждают физическим наблюдением одного сервисного шага.

В интерфейсе это отдельная кнопка «Пробный Home … отключить мотор в конце».
Штатная кнопка подписана «Home с удержанием». При STOP/ошибке любого активного
крана (включая штатный Home/Calibrate/Go) также запрашивается M18 только его оси.
Успешные штатные операции удержание и reference сохраняют. X/Y STOP не изменён.
