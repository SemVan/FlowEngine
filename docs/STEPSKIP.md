# Проверка возврата к физическому концевику X/Y

В FlowEngine реализован практический контроль потери позиции для откалиброванных
осей X/Y с параллельными концевиками. В интерфейсе он находится в разделе
**«Тест шагов»**.

Это **не энкодерное измерение ротора** и не абсолютное доказательство пропуска
шагов. Проверка измеряет ошибку возврата к одной и той же физической опоре.
На результат также влияют люфт, повторяемость микрика, муфта и упругость механики.

## Что является эталоном

После штатного Home FlowEngine сохраняет Marlin `Count`, полученный в момент
точного медленного latch на выбранном `home_side`. Reference действует только до
reconnect/reset/STOP, поэтому проверка шагов требует состояние `REFERENCED`.

## Протокол Check Steps

1. Ось должна быть физически откалибрована и иметь `REFERENCED`.
2. FlowEngine идёт к сохранённому `home_side` тем же механизмом, что Home:
   `fast seek → release → backoff → slow latch`.
3. В момент точного повторного касания читается новый Marlin `Count`.
4. Вычисляется `delta_steps = measured_count - baseline_count`.
5. Если `abs(delta_steps) <= tolerance_steps`, результат `OK`; FlowEngine снова
   назначает reference-координату и отходит от концевика.
6. Если допуск превышен, результат `STEP_LOSS`: абсолютная привязка этой оси
   считается недостоверной, `REFERENCED` снимается и требуется новый Home.

При `OK` исходный baseline последнего Home сохраняется, чтобы мелкая повторяемость
концевика не накапливалась как дрейф эталона от проверки к проверке.

## Интерфейс

Доступны кнопки:

- `Check Steps X`
- `Check Steps Y`
- `Check Steps X + Y`

Допуск задаётся в шагах. Начинать следует с допуска, выбранного по реальной
повторяемости медленного latch на стенде, а не с произвольного минимального числа.

Результат показывает baseline Count, фактический Count, Δ в шагах и состояние
reference после проверки.

## Что проверка не доказывает

Marlin Count — счётчик импульсов прошивки, а не энкодер двигателя. Само сравнение
`M114` с отправленной командой не обнаруживает потерю ротора. Здесь Count становится
полезен только потому, что его сравнивают **в повторяемой физической точке,
заданной концевиком**.

Для независимой количественной оценки положения нужен энкодер или внешнее
измерение. Pressure-ramp и автоматический поиск предельной скорости остаются
отдельной будущей задачей.
