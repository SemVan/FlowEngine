# Ограничения и проверка на стенде

Это рабочее место разработчика, не медицинский прибор и не система аппаратной защиты.
Наличие кнопки или поля не означает, что функция проверена на конкретной плате.
Новые функции проверяются на симуляторе; результаты аппаратных испытаний фиксируются отдельно.

## Что реализовано и что ещё нельзя обещать

| Пожелание | Реализация | Что проверить / ограничение |
|---|---|---|
| Порт и бодрейт | Фактическое подключение, профиль и состояние на главной | USB CDC может не использовать бодрейт как физическую скорость шины |
| STEP pulses/s и физические единицы | Ручное движение и `move`; `pump` в мкл и мкл/мин | Коэффициент объёма измеряется пользователем; `calibrated: false` блокирует дозирование |
| Ускорение | `acceleration` у движений; M204 читается и восстанавливается; M201 при configure_firmware | Дополнительные ограничения самой прошивки сохраняются; после разрыва связи восстановление не гарантировано |
| Общий концевик | `endstop_inputs`; запрет общего G28 и совместных движений этой группы | Конфиг не переназначает входы Marlin. Нужен проверенный firmware probe / адаптация прошивки |
| Последовательный хоуминг | Составная процедура `seek` → отход → следующее устройство | Все НЕдвижущиеся устройства должны освобождать общий вход |
| Расстояние между концами крана | `calibrate_valve`, повторы и разброс, отчёт в STEP pulses | Оба конца должны останавливать G38 через один проверенный probe; произвольные два входа пока не поддерживаются |
| Проверка пропусков | `test_reference` и сравнение измерений `/reference-error` | Это ошибка возврата к опоре, не доказательство числа пропущенных шагов |
| АЦП/термисторы | `analog_inputs`, преобразования, одноразовое чтение M105 | Обычный M105 даёт температуру; ADC доступен только если прошивка действительно публикует такой источник |
| Несколько моторов | `move_multi` / `pump_multi`, одна G1, общий номинальный интервал и соотношение перемещений/объёмов | Не независимые планировщики. Осевые единицы должны совпадать; разные времена окончания требуют отдельных участков |
| Терминал | Одна сырая команда через штатную очередь, подтверждение изменений, TX/RX | Сырые команды обходят семантические лимиты; не отправлять неизвестные команды / управление нагревом без знания схемы |
| Снятие удержания | M17/M18 выбранных осей или всех, сброс достоверности координат | Это не выключение БП. Возможны общие линии enable, движение под тяжестью/давлением |
| Ток удержания | Ограниченный M906 для проверенного рабочего тока; отдельное удержание явно недоступно | Нужны тип драйвера, UART/SPI, версия прошивки и поддерживаемый способ задания holding current |

## Не включать автоматически

- `motion.enabled` и `motion.configure_firmware`: значения заводского примера могут не подходить механике.
- `probe_target_verified`: выставляется только после проверки исходников прошивки и отдельного стендового испытания остановки по контакту.
- `verified_probe_axes`: не список желаемых осей, а список реально испытанных на probe осей.
- `verified_current_axes` и `driver_current_max_ma`: после проверки драйвера, двигателя, охлаждения и способа управления.
- `calibrated`: после реального измерения жидкости. Число 1 мкл/единицу в старом профиле — заглушка.

M115 не сообщает универсальную capability для G38. Поэтому приложение не выводит
поддержку G38 из наличия `ok`, из `Z_PROBE` или из названия Marlin.

## Конфигурация: пример, не готовая схема подключения

```yaml
# Внутри device_map
endstop_inputs:
  - channel: z_probe       # Точное имя из M119; не номер разъёма
    axes: [X, Y]          # Два разных устройства на общем входе
    active_high: true     # Документация электрической схемы; инверсия настраивается в прошивке
    notes: "У каждого устройства свой выключатель; общий вход освобождается после отхода"
analog_inputs:
  - name: liquid_temperature
    source: T0            # Только если M105 реально выводит T0
    quantity: temperature
    units: "°C"
    scale: 1
    offset: 0
    poll_hz: 1            # Желаемая частота; в этой версии чтение ручное / шагом процедуры

# Внутри runtime.firmware, ТОЛЬКО после стендовой проверки
probe_target_verified: false
verified_probe_axes: []
probe_channel: null
verified_current_axes: []
```

`active_high`, `dir_invert`, `endstop_inverted` не перепрошивают плату и не изменяют
аппаратную полярность. Ответ M119 уже использует трактовку TRIGGERED/open прошивки.
Изменение направления в механике необходимо согласовать с прошивкой, home_direction,
положениями кранов и dispense_direction.

## Главные опасения

1. **Общий вход постоянно замкнут.** Устройство, оставленное на концевике, блокирует поиск остальных.
   Последовательный запуск не решает электрическую неоднозначность. Проверить каждый выключатель
   отдельно и освобождение общего входа. При NC-схеме простое параллельное соединение может
   вообще не иметь ожидаемой логики; схему подтверждает специалист по железу.
2. **G38 отсутствует / поддерживает не все оси / действует другой вход.** Получение `ok` не доказывает
   остановку по контакту. Приложение дополнительно проверяет срабатывание, но это не защита от
   механического столкновения. Проверять в свободном ходе на минимальной скорости, с физической остановкой.
3. **Неправильный home_direction или знак насоса.** Проверить короткое движение каждой оси отдельно.
   Не использовать Home all, пока не проверены ВСЕ устройства. Сломанный Y-концевик не использовать.
4. **Открытый контур.** M114 и Count описывают состояние прошивки, не положение ротора.
   Люфт, проскальзывание муфты, повторяемость выключателя, пропуски разных направлений могут
   скрывать или имитировать ошибку. Для доказательства нужны независимое измерение / энкодер.
5. **Неверные шаги/единицу и микрошаг.** Проверить M503/M92 и драйвер. Переключение микрошагов
   или механики делает прежние коэффициенты и калибровки недействительными.
6. **Поток зависит от нагрузки.** Особенно у перистальтического насоса. Первый вариант использует
   постоянный коэффициент: создавать отдельные профили для разных условий; автоматической
   интерполяции кривой и обратной связи по потоку пока нет.
7. **Время движения.** duration_s — расчёт для участка с постоянной скоростью; реальное время
   больше из-за ускорения/торможения. Независимые расходы с разными моментами окончания нужно
   описывать согласованными участками; строгая независимость ускорений не реализована.
8. **Отмена и USB.** M410 может ждать обработки, особенно без EMERGENCY_PARSER.
   Отмена не гарантирует немедленного стопа. После Stop/ошибки протокола очередь закрыта до
   перезапуска; автоматической рассинхронизации ACK и продолжения не делаем.
9. **Моторы освобождены.** Механизм может сам сместиться. Приложение сбрасывает homed;
   включение мотора не восстанавливает координаты. Повторно установить опору.
10. **Токи и аналоговые входы.** Не считать TMC текущего профиля подтверждённым типом драйвера.
    Вход термистора не универсальный вход произвольного напряжения; совместимость, диапазон,
    защиту, опорное напряжение и разводку проверяет железячник. Не подавать напряжение силовых выходов на ADC.

## Порядок испытаний

- [ ] Сохранить копию текущего профиля и снять M115/M503/M119/M122; записать версию прошивки и драйверов.
- [ ] Убедиться, что интерфейс показывает нужный порт и профиль, а не симулятор.
- [ ] Проверить физическую аварийную остановку; проверить сценарий её использования без движения.
- [ ] По одной оси: направление, короткое движение, лимиты, единицы и фактическую скорость.
- [ ] Снятие удержания: поддержать механизм; проверить выбранную ось и остальные оси; повторно home.
- [ ] Ускорение: прочитать M204 до/после; проверить плавность и восстановление после обычного завершения.
- [ ] Собрать жидкость минимум в трёх повторах; записать скорость, направление, жидкость, нагрузку; сохранить коэффициент.
- [ ] Проверить дозирование независимым измерением, не теми же данными, по которым получен коэффициент.
- [ ] Две оси: проверить отдельно, затем совместно на малых перемещениях; измерить отношение и длительность.
- [ ] Только после проверки прошивки: по одному probe выключателю; потом общий вход, исходный контакт,
      отсутствие контакта, освобождение после отхода и последовательность двух устройств.
- [ ] Кран: проверить два конца вручную, затем низкоскоростное измерение хода и повторяемость.
- [ ] Возврат к опоре: подобрать допуск по низкоскоростным повторам; затем менять скорость/ускорение по одному параметру.
- [ ] Датчики: сравнить с известным значением, проверить отсутствующий источник (null, не 0), согласовать единицы.
- [ ] Полная процедура: сначала пошагово, затем целиком; отдельно отмена во время движения и во время ожидания.

Заполнять фактические результаты, не просто галочки. Экспорт session feedback сохраняет
активный конфиг, статус процедуры и последние 1000 TX/RX текущей сессии. После перезапуска
эта история исчезает. Добавить копию процедуры и фото/схему актуального подключения.

- [M105: температура, не универсальный ADC](https://marlinfw.org/docs/gcode/M105.html)

Ещё не реализованы: произвольное runtime-переназначение endstop на любую ось,
отдельный ток удержания, произвольный ADC-протокол, автоматический опрос заданной
частоты, независимые планировщики, энкодерная оценка потерь, pressure-ramp,
автоматический безопасный сценарий после ошибки. На ошибке процедура прекращается;
приложение не выбирает само, какие краны или насосы следует двигать.
