# Проверка developer workbench — 16 сентября 2026

## Выполнено

- Полный pytest: **92 теста прошли** (включая прежние тесты приложения).
- Ruff для новых модулей, схем, sender/runner, парсера/симулятора и новых тестов: без замечаний.
- `git diff --check`: без ошибок форматирования patch.
- Проверка синтаксиса JS-модулей через Node.
- Браузерный прогон через Firefox / Playwright на отдельном `--mock` экземпляре.
  Скрипт: [verify_workbench.mjs](../scripts/verify_workbench.mjs).

## Что проверено

- Координаты M114 не перезаписываются значениями Count; нестандартный probe вход разбирается.
- STEP pulses → осевые единицы, STEP/s → feedrate, объём → ход / расход → скорость.
- Некалиброванный насос не выполняет дозирование; измерения объёма/массы не запускают движение.
- Сохранение профиля и запуск приложения с ним; совместное дозирование двух откалиброванных насосов.
- Один G1 для нескольких осей; ограничения компонентных скоростей; отказ для разных времён окончания насосов.
- Конфигурация общего входа блокирует G28 и совместные движения этой группы.
- Probe-поиск без поддержки / с замкнутым входом отклоняется до движения.
- Калибровка хода по симулированным физическим крайним положениям и firmware STEP counters.
- Тест опорной ошибки с симулированной направленной потерей перемещения.
- Снятие удержания сбрасывает homed выбранной оси; включение не восстанавливает опору.
- M204 восстанавливается после штатного выполнения и обычной ошибки внутри операции.
- Отмена одиночного шага отслеживается; Stop не возвращает состояние idle / достоверные координаты.
- После ошибки очереди новые команды не используют поздний ACK как успешный ответ.
- Статический preflight всей вложенной процедуры блокирует неподдерживаемые операции до первого движения.
- Температурный источник доступен, отсутствующий ADC возвращает null, не фиктивный ноль.
- В браузере: viewer, единицы/ускорение, консоль, motor enable/release, калибровка,
  профиль, preview, запуск шага, формы новых операций и совместных насосов, экспорт файлов.
- Прежний Jog проверяется в браузере с Content-Type и Idempotency-Key, а не только прямым REST-запросом.

## НЕ проверено

В этом изменении никаких движений и диагностических команд реальной плате не отправлялось.
Симулятор не доказывает электробезопасность, точность расхода, поддержку конкретных
G/M-кодов, корректность объединения выключателей или физическую остановку.

Аппаратно-зависимые режимы остаются выключенными по умолчанию. Подробные опасения,
недоступные возможности и порядок испытаний: [COMMISSIONING.md](COMMISSIONING.md).

У pytest остаётся предупреждение совместимости установленного Starlette TestClient с httpx;
на результат тестов оно не повлияло. Весь репозиторий не объявляется полностью lint-clean:
в нетронутых модулях есть прежние замечания.

## Как повторить

```bash
source .venv/bin/activate
pytest -q
# Отдельная конфигурационная папка предотвращает изменение рабочего профиля.
FLOWENGINE_CONFIG_DIR=/private/tmp/flowengine-test-config python -m flowengine --mock --port 8877
```

Для браузерного прогона отдельно установить Playwright и соответствующий ему браузер.
Запуск не требует npm/build для самого приложения:

```bash
FLOWENGINE_PLAYWRIGHT=/path/to/node_modules/playwright \
FLOWENGINE_TEST_URL=http://127.0.0.1:8877 \
node scripts/verify_workbench.mjs
```

Не запускать против рабочего сервера: тест откажется от real transport, но создаёт
тестовые профили/процедуры и двигает симулятор. Для уже установленного совместимого
Firefox можно передать полный путь исполняемого файла через FLOWENGINE_FIREFOX.
